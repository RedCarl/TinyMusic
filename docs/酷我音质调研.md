# 酷我音质调研：为什么只接入 128k / 320k / FLAC

> 实测时间：2026-11-10，本机网络。第三方接口会变，以下只代表当日行为。

## 1. 目录里确实有 6 档

搜索/歌单响应的 `MINFO` / `N_MINFO` / `FORMATS` 会列出：

| 档位 | 酷我格式标记 | 状态 |
|---|---|---|
| 标准 128k | `MP3128` / `level:h,format:mp3,bitrate:128` | 可播 |
| 高品质 320k | `MP3H` / `level:p,format:mp3,bitrate:320` | 可播 |
| 无损 FLAC | `ALFLAC` / `level:ff,format:flac` | 可播（按曲目） |
| Hi-Res | `ZPGA201` / `ZPGA501` / `ZPGA714` / `ZPLY` | 加密，未接入 |
| 杜比全景声 | `DTSX` / `BCMS` / `DDJOC*` / `AC4256` | 加密，未接入 |
| 母带 | `ZPLY` / `MNAC440` | 加密，未接入 |

## 2. 公开匿名链路能拿到什么

`musicinfo`（`itemset=music_2014&alflac=1&pcmp4=1`）只返回这些格式的 S1/S2：

```text
MP3H=...   # 320k
MP3128=... # 128k
ALFLAC=... # FLAC
```

`anti.s` 对高级 `br`（`zpga201` / `zply` / `dtsx` / `bcms` / `mnac440` / `hires` / `atmos` / `master`）
一律返回 181,521 字节占位文件（URL 含 `588957081`），不是真音频。

`yl_res_manage` 依赖 musicinfo 的 S1/S2；没有高级格式签名就拼不出请求。

## 3. 实测样本

《稻香》`440613`：

| 请求 | 字节 | 实际 |
|---|---|---|
| 128k | 3,576,668 | MP3 128k |
| 320k | 8,940,938 | MP3 320k |
| 无损 | 26,012,257 | `fLaC`，44.1kHz / 16bit / 2ch / 223.45s |

抽 18 首搜索结果：9 首有 `ALFLAC`，9 首没有。所以无损必须按曲目判断，不能全局永远可点。

## 4. 后三档要真正可播，需要什么

1. **会员权益**：当前只保存酷我 uid，没有 cookie/session；匿名请求不返回高级签名。
2. **加密 URL + ekey**：需要逆向 PC 客户端协议或依赖私有后端。
3. **QMC2/DES 解密**：`kuwo-music-relay` 已实现，但许可证是 PolyForm Noncommercial，不能直接复制/内置。
4. **容器/编解码**：`.mflac` 解密后是 FLAC；`.mgg` 是 OGG；`.mmp4` / `.mnac` 的全景声/母带 WebView 未必支持。
5. **合规**：接入 VIP 付费内容会改变项目「只做匿名公开接口」的立场。

结论：本次只把 6 档模型和 UI 补齐，后三档明确灰色；真正可播需要单独的 VIP + 解密 + 编解码专项。
